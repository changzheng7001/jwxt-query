# 闪电优化 · 实验日志

## 改动 1：查询请求 同步 → 异步（消除 UI 冻结）

- **日期**：2026-09-28
- **假设**：`httpGet/httpPost` 同步调 `Android.httpRequest`（@JavascriptInterface 同步阻塞），JS 线程等待网络请求 → WebView 主线程冻结。改为原生后台线程请求 + JS 回调（Promise），UI 不再冻结。
- **做法**（最小逻辑单元，前端/原生必须同步改才能工作）：
  - 前端 index.html：
    - `httpGet/httpPost` 改为 Promise + `window.__httpDone` 回调注册表
    - `doLogin`、`doQuery` 各 case、`openBrowse` 全部 14 处调用加 `await`
  - 原生 smali：
    - `followRequest` private→public，两处 `invoke-direct`→`invoke-virtual`
    - `MainActivity` 新增 `-$$Nest$fgetwebView` 桥
    - `WebAppInterface` 新增 `httpRequestAsync(method,url,body,cb)`（@JavascriptInterface，立即返回）
    - 新增 `HttpAsyncRunnable`（后台线程执行 followRequest + JSONObject.quote 转义）+ `HttpAsyncRunnable$1`（webView.post 切主线程 loadUrl 回调）
- **确定性计数**：同步阻塞（UI 冻结时长=请求耗时）→ 0（JS 不再等待）
- **验证**：
  - 前端语法 OK（node 编译所有 script 块）
  - 前端 14 处调用全部 await，无遗漏
  - apktool 重编译成功，`HttpAsyncRunnable`/`HttpAsyncRunnable$1` 编入 classes2.dex，`httpRequestAsync` 注册
  - 签名成功
- **是否保留**：待用户真机验收（界面不卡 + 各查询返回同样结果）
- **风险**：followRequest 后台线程读 cookieStore，与 addCookie（JS 线程）可能并发；单查询场景风险低，真机若异常再处理
