# 闪电优化 · 开工简报 (BRIEF)

## 产品
中警院教务查询 App（com.cicp.jwxt，v0.9.7）—— WebView 套壳 + 本地单文件 index.html + 原生同步 HTTP 桥。

## 核心操作（用户确认）
打开 App → 查询（教师 / 教室 / 班级 / 课程 / 本人课表 / 成绩 / 进度 / 学籍 / 选课）。

## 什么叫「能用」（用户确认）
**界面不卡**：查询点下去，界面能响应（可滚动、可操作），不被请求冻结。

## 不能动（用户确认）
- 视觉、主题保留；新的可增加但作为可选，不影响原样
- 姓氏表（SURNAMES）不动 —— 保证拼音分组全准
- 功能语义不变（各查询仍返回同样结果）

## 目标（用户确认「可以」）
查询时 **UI 无响应时长 p75 减半**。

## 根因（已代码确认）
`httpGet/httpPost`（index.html L817-818）同步调用
`Android.httpRequest`（`@JavascriptInterface` 同步返回，smali `MainActivity$WebAppInterface.httpRequest`）。
JS 线程调它时 WebView 主线程被网络请求阻塞 → 界面冻结。
改造方向：**同步 → 异步**（原生后台线程请求 + JS 回调），冻结时长趋近 0。

## 基线口径
- 代理指标：`Android.httpRequest` 同步调用阻塞时长（≈ UI 冻结时长）= 网络往返 + 原生处理 + 同步等待。
- 真机基线：临时埋点（performance.now 前后差 + 界面 debug 输出），用户装包报 p75。
- 改造后该阻塞=0（JS 不再等待），p75 减半目标确定性达成。

## 上线批准（用户确认）
替换 v0.9.7 安装包（不 bump 版本），用户装包验收「界面不卡」即算数。

## 风险与护栏
- 改动涉及 smali（新增异步桥）+ 前端全部查询调用点 async 化，属大改 → 分小步、每步重打包验证、改崩即回退。
- 护栏：改造后各查询类型仍返回与原来相同的结果（功能冒烟）。
