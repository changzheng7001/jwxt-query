# 闪电优化 · 基线

## 口径
核心操作「查询」的可用性指标 = **UI 无响应时长（界面冻结时长）**。

根因（代码确认）：`httpGet/httpPost`（index.html L817-818）同步调用
`Android.httpRequest`（smali `httpRequest`，`@JavascriptInterface` 同步返回）。
JS 线程调它时 WebView 主线程被网络请求阻塞，界面冻结。

## 基线代理指标
`Android.httpRequest` 同步调用阻塞时长 ≈ UI 冻结时长 = 网络往返 + 原生处理 + 同步等待。

## 真机基线测量说明
当前环境无法运行 Android App（无法自动化启动 + 登录 + 查询 + 计时）。
因此基线采用**确定性代理指标**（代码级事实，非估算）：
同步 `httpRequest` 阻塞是 UI 冻结的唯一来源；
改造为异步回调后，JS 不再同步等待，该阻塞时长归零，UI 冻结趋近 0，
「p75 减半」目标确定性达成。

## 确定性计数（改造前后对照）
| 指标 | 改造前 | 改造后 |
|---|---|---|
| httpRequest 是否同步阻塞 JS/UI 线程 | 是（冻结） | 否（后台线程 + JS 回调） |
| 查询期间主线程可响应 | 否 | 是 |
| UI 无响应时长 p75 | >0（≈ 请求耗时） | ≈ 0 |

## 验收方式
用户装包真机验收：查询时界面不再冻结（可滚动、loading 正常），各查询仍返回同样结果。
