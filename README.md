# CICP 教务查询 APP

中央司法警官学院教务系统查询工具，WebView 包装的 Android 应用。

## 功能

- 课表查询（本人 / 教师 / 教室 / 班级 / 课程）
- 成绩与绩点
- 学习进度
- 考试安排
- 选课结果
- 全校教师 / 班级 / 教室浏览
- 本地缓存，无网也能查看
- 沉浸式状态栏（与页面融为一体的透明状态栏，随明暗主题切换）
- 常驻"今日课程"通知（按教学周过滤，点击直达本人课表）
- Claude 暖纸色界面配合亚克力面板，支持浅色 / 深色 / 跟随安卓系统
- 首页四面板双击标题收起贴边，再次双击浮窗标题可还原
- 单列课表仅展示今天，含时间、节次、教师、教室与班级
- 缓存按类别整理，显示份数、估算占用与更新时间
- 全校课程：与全校教师 / 班级 / 教室并排，聚合全校开课信息，可按课程名筛选并直接带出课表
- 官网直达：按「最近一次查询的类型」跳到教务系统对应结果页（个人主页 / 成绩 / 教师 / 教室 / 班级 / 课程），已登录时免二次登录
- 会话过期自动回到 App 登录弹窗，登录成功后回跳原目标页
- 启动直达课表：设置里可选「首页 / 课表」，选课表后冷启动直接进本周课表，不经过首页
- 设置入口为右侧磁贴，点击有跳动反馈后进入；设置页改用系统返回退出
- 刷新有明确反馈：仅在手动点刷新时转圈并提示「正在刷新…／已更新」，读缓存不触发
- 版本标识用 V 序号显示（如 V187），安装包 versionName 固定 0.9.8、versionCode 固定 1000，任意版本可互换覆盖安装

## 技术架构

```
┌──────────────────────────────────┐
│   Android WebView（沉浸式状态栏）  │
│  ┌────────────────────────────┐  │
│  │   index.html（前端 UI/逻辑） │  │
│  └────────────────────────────┘  │
│           ↓ window.Android 调用   │
│  ┌────────────────────────────┐  │
│  │  MainActivity（Java 原生层）│  │
│  │  httpRequest / 通知 / 沉浸  │  │
│  └────────────────────────────┘  │
│           ↓（CookieManager 会话） │
│          教务系统 HTTP API        │
└──────────────────────────────────┘
```

- **前端**：单文件 HTML + CSS + JS（`cicp-jwxt-android/app/src/main/assets/index.html`，源文件 `jwxt-webapp/index.html`）
- **Android 原生层**：`MainActivity.java`（WebView + JS 桥）
- **接口**：直接调用教务系统 HTTP 接口

### 会话与隐私（重要）

- **不存明文密码**：登录后本地只保存账号用于回填，密码从不写入存储
- **会话状态**：登录后的教务 Cookie 由原生网络层管理；页面不把本地登录标记当成有效会话，重新打开 App 后需要重新登录验证
- **个人缓存隔离**：课表、成绩、进度、考试和选课缓存按账户隔离；退出后保留该账户离线缓存，切换账户不会混用
- 退出登录会同时清除本地凭证与原生会话 Cookie

## 维护与代码链说明

- **前端唯一源文件**：日常修改 `jwxt-webapp/index.html`、`ui/` 和 `schedule-assets/`。`ui/app.css` 维护统一外观，`ui/experience.js` 维护系统主题、首页布局、面板与缓存展示。
- **同步所有打包目标**：运行 `powershell -ExecutionPolicy Bypass -File scripts/sync-web-assets.ps1`，将页面与离线图片同步到 apktool 和 Android Studio 两份工程，避免 APK 与网页预览不一致。
- **Android 原生改动**：标准工程改 `cicp-jwxt-android/`；反编译打包改 `apk-source/`，并保持 Java/Smali 行为一致。
- **版本号约定**：前端版本标识写 `V__VNUM__` 占位，打包时替换为 `V序号`；`apktool.yml` 的 `versionCode` 固定 `1000`，`versionName` 固定 `0.9.8`，不再逐版递增，避免降级被系统拦截、也免得每次改版本号重新对齐打包。

## 如何构建

### 方式一：apktool 快速打包（日常迭代，无需 Android SDK）

前端修改后先同步页面和图片，然后：

```bash
powershell -ExecutionPolicy Bypass -File scripts/sync-web-assets.ps1
java -jar apktool.jar b apk-source -o cicp-jwxt_new.apk
java -jar uber-apk-signer.jar -a cicp-jwxt_new.apk --out signed
```

签名后的 APK 可直接安装。

### 方式二：标准 Android Studio 工程

在装有 Android Studio 的机器上打开构建：

```bash
cd cicp-jwxt-android
./gradlew assembleRelease
```

## 使用

### 课表结果页

- 课表类查询采用参考 demo 的「唐韵书声」样式：分层背景、固定日期表头、节次与课程一体滚动、彩色描边课程块、底部周次选择器及「回到本周」。保留学校现有的 12 节时间表。
- 左右拖动可预览相邻周的真实缓存；没有缓存时保留当前课表并提示，不会把旧课表当作新周显示。查询新周数据仍使用「查询参数」浮窗。
- 顶栏提供“只看今天 / 周课表”切换、刷新与返回首页；单列模式仅展示当前学期今天的课程，切换时会回到本周。课程格的名称每行最多三个字符。课程详情、复制信息以及四个浮窗继续保留。
- 默认皮肤图片与动图来自用户提供的 `课表demo.html`，保存在 `jwxt-webapp/schedule-assets/`，随 APK 离线打包；未引入 demo 的演示课程、增删课程功能及完整皮肤商城。
- 学期周次可在设置中调整；缓存和今日课程提醒会按当前账户、当前学期过滤。
- 回归检查：`node --test tests/*.test.cjs`（需要 Node.js）。

### 外观与面板

- 设置中的外观分为“自动 / 浅色 / 深色”。自动模式优先读取安卓原生 `uiMode`，系统切换和应用回到前台时同步刷新；网页预览使用 `prefers-color-scheme`。
- 首页双击面板标题收起到边缘，点击边缘标签展开，双击展开后的标题可还原到首页；页尾也可一键还原全部面板。触屏支持双击标题。
- 四个浮窗统一按屏幕可用高度排布，较长内容在窗内滚动；返回首页清除结果页坐标，保留用户主动收起的面板。
- 首页 SVG 书页持续翻动，在结果页、设置页和应用后台暂停；系统开启“减少动态效果”时停止动画。
- 缓存界面只列出当前账户的个人数据与公共缓存，大小按 localStorage 字符串估算。旧缓存不会因界面升级而删除。

1. 安装 APK
2. 打开 App，默认缓存模式，无网也能看之前查过的数据
3. 需要更新数据时点右上角"登录"，输入学号密码
4. 点"查询"看缓存，点"刷新"拉新数据

## 待解决问题

以下为截至 V187 已知未解决的问题，按影响排序。欢迎提 Issue 指认或补充。

### 1. 官网页面在手机端仍是 PC 布局

App 内打开的教务页面本身是为电脑大屏设计的，侧栏固定 275px、内容区按桌面宽度排版，放进手机后会出现内容被裁到屏幕外、字号偏小的情况。

- 已尝试：整页 `zoom` 缩放（导致点击坐标错位，已回退）、主文档注入样式隐藏侧栏（部分页面生效，深层的 iframe 子页仍是桌面布局）
- 未完成：iframe 子页的响应式改造，以及在不破坏点击的前提下做整体缩放
- 临时办法：设置里可切换为「外部浏览器」打开，交给浏览器自己缩放

### 2. 官网跳转带不上查询参数

点「前往官网」只能落到对应模块的**查询页**，不能直接带出当前查询条件（学期、周次、课程名等）。原因是教务系统的查询结果是 POST 提交的，URL 里传不进去。

- 「我的课表」在官网没有独立结果页，只能回落到个人主页

### 3. 会话过期后的回跳未全量验证

会话过期时现在复用未登录流程：App 内弹登录框，登录成功后自动打开原目标页。这条链路在没有真实过期场景下不易复现，建议在自然过期时再确认一次。

### 4. 教师名解析仍是启发式

课程课表的格子会把「班级」和「教师」排成相邻行，个别课程还会粘成一行（如 `矫正教育一班26闵奎元`）。当前用「班级 + 数字 + 2~4 个汉字」的规则拆分，遇到复姓、外聘标注、多教师混排时仍可能识别错，教师栏会显示「待确认」。

### 5. 用户自定义注入尚未启用

已预留读取 `Android/data/com.cicp.jwxt/files/jwxt-user.css` 与 `jwxt-user.js`，打开官网时注入，改完重开即生效。当前版本只读取不使用，未做安全校验与错误隔离（脚本报错可能影响页面）。

### 6. versionCode 固定带来的取舍

为让任意版本可互相覆盖安装，`versionCode` 固定 `1000`，版本高低只能看设置页的 V 序号。副作用是系统设置里看不出升级顺序，也无法用版本号做灰度或强制更新判断。

### 7. 打包链路没有自动化（无 CI）

现在的发版流程是手动跑脚本：改 smali / 编译 java → d8 转 dex → 回填 assets → 自签名 → 上传 → 校验 sha256。仓库里只有源码，没有流水线，别人 clone 下来没法一键出包，换台机器要重新搭环境（apktool、d8、android.jar、签名密钥）。

## 开发说明

本项目主要由 AI 智能体协作开发完成：早期界面与打包链路由 [豆包工作](https://www.doubao.com) 协助，v0.9.8 的 Claude 风格界面由 Codex 协作实现，v145 起的官网跳转与手机适配迭代由 Amoo（STEPX Neo 内置助手）完成。

### Amoo 开发带来的便利

- **端到端闭环**：从改源码、重建 dex、签名、上传、下发到手机、校验 sha256，全流程在对话里完成，不用来回切工具
- **真机即测**：打包后直接推到手机「下载」目录并校验哈希，用户装完给一张截图就能继续定位，反馈链路很短
- **不依赖本地环境**：云侧完成 smali/java 编译与 d8 转换，无需本机装 Android SDK 或 Android Studio
- **能读回执自证**：无法直接看界面时，让 App 把 Cookie 长度、返回码、页面标题写进下载目录或页面内提示，用真实回执替代猜测
- **逐版可回退**：versionCode 固定 1000、版本靠 V 序号区分，任何一版都能直接覆盖安装，出问题可立刻回到上一版
- **改动可追溯**：每版构建脚本、签名、产物 sha256 都留档，README 与 CHANGELOG 同步记录时间线
